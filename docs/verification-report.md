### 3.2 原切分的问题（先离线跑 parser + splitter 确认）

1. **枫原 docx 的表格没有转成键值对**：Docling 输出的是 Markdown 表格，被字符切分器从行间切开。MBA 那一行单独成为一个 chunk，没有表头，“3.0 / 4.0”“GMAT 600”看不出属于哪一列。“一、项目要求一览”这个标题也和表格分到了不同的 chunk。
2. **chunk 末尾挂着孤立的标题**：overlap 把下一节的标题带进了上一个 chunk 的末尾，例如“## 四、申请轮次与截止日期”“## 三、退费政策”“## Q6”。没有发现问答被从中间切断的情况。
3. 北岸理工的两张表（开放项目、申请轮次）在原切分下是完整的；6 份文档的虚构声明都在 chunk 0。

### 3.3 修复（`backend/app/ingestion/splitter.py`）

- 表格的每个数据行转成 `- 项目：…；学制：…；GPA 最低要求：…` 这样自带字段名的一行，跳过空单元格，保留转义的竖线。
- 按标题分节：只有标题、没有正文的父节会并入下一节；只有单个小节超过 `CHUNK_SIZE` 时，才退回字符级递归切分，并给后续片段补上标题。同时写入 `section_path`。
- 第二轮修复（由测评 case_022 发现，见 5.3）：**不跨一级小节打包**。文档标题和顶部声明并入第一个小节，同一个一级小节内的子节仍然打包。
- 只对 Docling 输出（`format=markdown`）生效。SQL Agent 的 YAML schema 仍走原来的递归切分，否则 YAML 注释 `# ...` 会被误认成标题。

## 7. 未解决的问题与观察

1. **case_025 的期望需要作者决定**（见 5.3）。
2. **RAGAS 指标的有效样本偏少**：full #2 中 answer_relevancy 只有 8/22 条有值，faithfulness 有 14/22 条。case_005、006 的答案与文档一致，却被评为 faithfulness 0。RAGAS 指标波动较大，建议以引用命中率和拒答正确率为主要参考，并排查 RAGAS 评判调用失败的原因（这次没有排查）。
3. **停止后不保存部分答案**：后端在连接断开时取消生成，只保存了 user 消息。刷新页面后部分答案消失，历史里会留下一条没有回复的问题。要在取消时可靠地落库，需要处理 anyio 的取消作用域，这次没有改。
4. **上下文改写结果在界面上看不到**：改写后的问题只记录在 `agent_steps[].query` 里，`query_route.rewritten_query` 为 null，且路由为 original 时面板是隐藏的。
5. **引用列表展示全部 top_k 检索结果**，而不是答案里真正引用到的编号，所以会出现无关文档。
6. **下载链接把 JWT 放在 URL 参数里**（`/api/documents/{id}/file?token=…`），会进入浏览器历史和访问日志。建议改成短期的一次性下载票据。
7. **一级小节偏短时 chunk 很小**（最短 49 字符，例如“联系方式”这类小节），目前没有合并过短的小节。
8. **README 与实际情况的差异**：功能表里的“节点步骤面板”实际只在多轮或非 original 路由时显示；技术栈里写的默认模型 qwen-plus 与本次运行的 `CHAT_MODEL` 不同（测评结果按实际配置记录）。
9. **语义缓存清理**：验证过程中删除过 Redis 中**由本次验证产生**的语义缓存条目（修复前写入的结果），没有触碰其他缓存，也没有删除数据库数据。
