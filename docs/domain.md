# NL2SQL 与知识库上下文

本项目同时维护可检索的产品文档知识库和用于问数演示的业务测试数据。两者共享 PostgreSQL 基础设施，但职责不同：知识库提供语义描述，业务表提供可执行数据。

## 领域语言

**知识库文档**：通过文档管理维护、切分并向量化后存入 `documents` 与 `document_chunks` 的可检索内容。Schema 描述 YAML 以文档形式进入知识库，而不是旁路配置表。
_避免_：Schema 表、向量表

**Schema 描述文档**：面向 SQL 生成和检索的人工维护文档，描述表用途、字段业务含义、字段类型以及允许的关联路径；字段事实可由 PostgreSQL 表结构补齐。
_避免_：只有字段名的数据库快照

**业务测试表**：位于 PostgreSQL `nl2sql_demo` schema 中、用于可重复问数演示的 `loan_records` 与 `repayment_plans` 表。
_避免_：生产业务表、知识库表

**语义层指标**：以 YAML 定义的标准指标口径，包含别名、公式、时间字段和可拆分维度；命中后由 Python 确定性拼接 SQL。
_避免_：让模型自由猜测的指标

**四元组**：查询解析产出的“指标、维度、过滤条件、时间范围”四个结构化字段，是语义层匹配和 SQL 生成的输入。
_避免_：直接把自然语言原句交给 SQL 执行器

**指标候选检索**：查询解析前从 Schema 描述文档的指标块召回候选内容，再交给 LLM 约束四元组中的指标名称。
_避免_：把全部指标配置无条件塞进 Prompt

**本地 Schema 导入**：开发演示命令将 Schema YAML 按现有文档切分和向量化逻辑写入知识库表，不经过 COS 和 Celery；它与生产文档上传共享数据模型，但不是生产上传接口。
_避免_：旁路维护一套 Schema 向量表
